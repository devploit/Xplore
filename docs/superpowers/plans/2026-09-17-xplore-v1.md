# Xplore v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the fully local X analytics sidebar described in `docs/superpowers/specs/2026-09-16-xplore-local-extension-design.md`.

**Architecture:** Two content scripts (MAIN-world interceptor, isolated-world sidebar), Dexie database, generic GraphQL normalizer, query-id registry fed by observation, throttled active X client, pure analytics functions, Preact UI in a shadow root.

**Tech Stack:** TypeScript strict, Vite (two IIFE entries), Preact + signals, Dexie, Chart.js 4, html-to-image, Tailwind, Vitest + fake-indexeddb.

**Rules for every task:** test first, `npm test` and `npm run typecheck` green before commit, Conventional Commits, no URL outside x.com/twitter.com/twimg.com.

## Phase C (optional, only if a real need appears): remote store

Not needed: every v1 feature works with IndexedDB alone (verified 2026-09-17 with `npm run e2e`). If backup or off-browser follower snapshots become necessary, add `server/` (single Go or Node binary) listening on `xplore.0x41.eu:4949` behind TLS, accepting only requests with header `X-Xlytics-Key: <random 32-byte secret>` compared in constant time, storing JSON snapshots per user, and an opt-in setting in the extension that is off by default. This would be the only host added to the allowed list and the build guard.

## Verification record (2026-09-17)

- `npm run verify`: typecheck clean, 75 unit tests green, build 371 kB sidebar + 3.4 kB interceptor, bundle guard green (no host outside x.com, twitter.com, twimg.com; no eval).
- `npm run e2e`: headless Chrome 153 with the extension loaded through `Extensions.loadUnpacked` against a local fake X. Passive capture stored tweets and users from both fetch and XHR, observed query ids replaced the seed, follower snapshot written, first backfill walked two pages with the observed id and CSRF header, mentions search ran, all six pages rendered with data, zero console errors.
- Found and fixed along the way: Chrome rejects content scripts with a literal U+FFFF (Dexie), solved by escaping non-ASCII at build time; the first backfill must not stop at pages already captured passively.
- Not verified here: behavior against the real x.com with a logged-in session (needs the user's browser). Acceptance items 5 to 9 of the spec remain manual.
