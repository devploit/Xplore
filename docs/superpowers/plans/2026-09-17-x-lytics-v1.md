# x-lytics v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the fully local X analytics sidebar described in `docs/superpowers/specs/2026-09-16-x-lytics-local-extension-design.md`.

**Architecture:** Two content scripts (MAIN-world interceptor, isolated-world sidebar), Dexie database, generic GraphQL normalizer, query-id registry fed by observation, throttled active X client, pure analytics functions, Preact UI in a shadow root.

**Tech Stack:** TypeScript strict, Vite (two IIFE entries), Preact + signals, Dexie, Chart.js 4, html-to-image, Tailwind, Vitest + fake-indexeddb.

**Rules for every task:** test first, `npm test` and `npm run typecheck` green before commit, Conventional Commits, no URL outside x.com/twitter.com/twimg.com.

---

## Phase A: data platform (produces an extension that captures data, visible in DevTools)

- [ ] **Task 1: scaffold.** `package.json`, `tsconfig.json`, `vite.config.ts` (entries `src/interceptor/index.ts` and `src/ui/main.tsx`, IIFE, `dist/`), `manifest.json` (MV3, two content scripts, min Chrome 111, no permissions), `.gitignore`, Vitest config with `fake-indexeddb/auto`. Smoke test: `tests/unit/smoke.test.ts`. Commit `build: scaffold extension with vite, preact and vitest`.
- [ ] **Task 2: shared messages.** `src/shared/messages.ts`: `GraphqlMessage`, `DroppedMessage`, `NavigateMessage`, union `XlMessage`, guard `isXlMessage(data)`. `src/shared/x-urls.ts`: `GRAPHQL_RE`, `parseGraphqlUrl(url) -> {queryId, op} | null`, `ALLOWED_HOSTS`. Tests for guard and parser.
- [ ] **Task 3: interceptor.** `src/interceptor/index.ts`: wrap `fetch` and XHR, clone, parse, `postMessage`; size cap 8 MB; swallow errors. `src/interceptor/router-capture.ts`: `Object.prototype.history` trap, `navigate` handler. Tests with a fake `fetch`.
- [ ] **Task 4: database.** `src/data/db.ts`: Dexie `xlytics` v1 with tables from spec 3.4, typed rows `TweetRow`, `UserRow`, `FollowerSnapshotRow`, `QueryIdRow`, `RateLimitRow`, `BackfillRow`, `TimelineRow`, `SettingRow`. Test opens DB and round-trips a tweet.
- [ ] **Task 5: normalizer.** `src/data/normalizer.ts`: `normalizeGraphql(body) -> {tweets, users}` generic walker per spec 3.5. Fixtures in `tests/fixtures/` for UserTweets (timeline and timeline_v2, item and module entries), TweetDetail, SearchTimeline, UserByScreenName with `core.screen_name`, TweetWithVisibilityResults, note tweet. Tests per fixture.
- [ ] **Task 6: ingest.** `src/data/ingest.ts`: `ingestMessage(msg)` normalizes, `bulkPut`s, updates `queryIds` with `source: "observed"`, writes follower snapshot when the current user is seen. Tests with fake-indexeddb.
- [ ] **Task 7: query-id registry.** `src/data/queryIds.ts`: `SEED` (25 ops from research 03, with features sets A, A2, MIN, LIST_TL and UserByScreenName features), `getQuery(op)` returns observed over seed, `markStale(op)`. Tests for precedence.
- [ ] **Task 8: rate limits.** `src/data/rateLimit.ts`: `parseLimitHeaders(headers)`, `decide(limit, opts) -> {ok, waitMs}` per spec 3.7, `backoff(attempt)`. Tests.
- [ ] **Task 9: X client.** `src/x-api/client.ts`: `xGet(op, variables)` and `xPost(op, variables)` building URL/body from registry, headers from `ct0`, typed errors, rate-limit bookkeeping. `src/x-api/operations/*.ts`: `userTweets`, `userTweetsAndReplies`, `userByScreenName`, `userByRestId`, `searchTimeline`, `tweetDetail`, `listLatestTweets`, `listByRestId`, `listsManagement`, `listMembers`, list mutations, `favorite`, `unfavorite`, `retweet`, `unretweet`, `bookmark`, `unbookmark`. `src/x-api/cursor.ts`: `bottomCursor(body)` by `cursorType === "Bottom"`. Tests with mocked `fetch`.
- [ ] **Task 10: identity.** `src/data/identity.ts`: `currentUserId()` from `twid` cookie, `currentUser()` from `users` table. Tests.
- [ ] **Task 11: jobs.** `src/data/jobs/lease.ts`, `backfill.ts`, `refresh.ts`, `followers.ts`, `mentions.ts`, `prune.ts`, `scheduler.ts` (runs jobs per spec 3.8 with timers). Tests for lease, prune and backfill stop conditions with mocked client.
- [ ] **Task 12: sidebar bootstrap (data only).** `src/ui/main.tsx`: message listener, ingest, start scheduler, mount an empty shadow host with a debug counter. Build, load unpacked, verify capture in DevTools. Commit.

## Phase B: analytics and UI

- [ ] **Task 13: analytics core.** `src/analytics/{types,split,buckets,series,media,followers,ranking,heatmaps,earnings}.ts` per spec 3.9. Full unit coverage with synthetic tweets.
- [ ] **Task 14: UI shell.** Shadow host, theme observer, layout body classes, toggle button, router, store (signals), settings persistence in `settings` table, toast.
- [ ] **Task 15: Home page.** Highlights and Recents with tweet card and quick actions.
- [ ] **Task 16: Activities page.** Period selector, frequency heatmap, engagement block with Chart.js line charts, hour by weekday heatmap, media categories, followers chart, earnings toggle.
- [ ] **Task 17: Tweets page.** Sortable table, tabs, search, best and worst views.
- [ ] **Task 18: Mentions page.** Filters, sorting, mentions job trigger.
- [ ] **Task 19: Timelines page.** CRUD for custom timelines, three sources, cursor infinite scroll, manual refresh.
- [ ] **Task 20: posters.** Poster modal with 16 styles, html-to-image export, clipboard copy.
- [ ] **Task 21: settings page.** Theme, layout, page toggles, rate-limit status, retention, export JSON, delete all.
- [ ] **Task 22: build guard.** `tests/build/no-external-hosts.test.ts` over `dist/`; `npm run verify` runs typecheck, unit tests, build and the guard.

## Phase C (optional, only if a real need appears): remote store

Not planned for v1. If backup or off-browser follower snapshots become necessary, add `server/` (single Go or Node binary) listening on `x-lytics.0x41.eu:4949` behind TLS, accepting only requests with header `X-Xlytics-Key: <random 32-byte secret>` compared in constant time, storing JSON snapshots per user, and an opt-in setting in the extension that is off by default. This would be the only host added to the allowed list and the build guard.
